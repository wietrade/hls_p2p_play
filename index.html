📺 hls_p2p_play 使用说明

ArtPlayer + P2P（p2p-media-loader）HLS 播放器 · 100% 全宽 · 可 iframe 嵌入 · iOS 兼容

一、这是什么

play.html 是一个基于 ArtPlayer + p2p-media-loader（WebRTC 数据通道）的 HLS 流媒体 P2P 播放器。观众之间通过 WebRTC 互相分享视频分片，降低源站带宽压力。

  • ✅ 纯静态 HTML，无需服务器，任何静态托管/CDN/本地均可部署
  • ✅ 100% 全宽播放器，专为 <iframe> 嵌入设计
  • ✅ iOS 17.1+ 走 ManagedMediaSource 支持 P2P；老 iOS 自动回退原生 HLS
  • ✅ 移动端自适应（手机/平板/桌面）
  • ✅ P2P 引擎常驻，切流不重建

播放器页面：play.html（与本文档同目录，部署到任意域名均可直接访问）

🎬 在线试玩

💡 在输入框改流地址后点「▶ 播放」即可换源；也可直接用 ?url= 参数带流地址打开播放器页面。

二、快速开始

1. iframe 嵌入到你的网站（其他网站调用）

<!-- 其他网站调用：只需在播放器 URL 后追加参数 -->
<iframe src="https://你的域名/play.html
        ?url=你的m3u8流地址     <!-- 必填：视频流地址（http/https）-->
        &tracker=可选           <!-- 可选：追加 Tracker，逗号分隔 -->
        &stun=可选              <!-- 可选：追加 STUN，逗号分隔 -->
        &noturn=1               <!-- 可选：传 1 关闭 TURN 中继 -->
        &stats=0                <!-- 可选：传 0 隐藏统计悬浮层 -->"
        style="width:100%; aspect-ratio:16/9; border:0;"
        allowfullscreen></iframe>

三、参数说明（其他网站调用）

其他网站通过 <iframe> 调用时，只需在播放器 URL 后追加以下参数。唯一必传的是 url（流地址），其余参数均可省略（使用默认值）。

参数说明默认值
url 必填 视频流地址（.m3u8，http/https）。缺失或非法时用内置测试流 内置测试流
tracker 可选 WebTorrent Tracker 地址（逗号分隔，须 ws:// 或 wss://）。追加到默认 tracker 之后，不覆盖；非法项自动丢弃 wss://bot3.1230sb.com/tracker 等 4 个（自建 + 公共，多 tracker 容错）
stun 可选 STUN 服务器（逗号分隔，须 stun:/turn:）。追加到默认之后，不覆盖；非法项自动丢弃 4 个公共 STUN
noturn 可选 传 1 关闭自建 TURN 中继（默认开启，用于公网对称 NAT 兜底） 开启
stats 可选 传 0 隐藏视频框内统计悬浮层（HTTP/P2P 下载、上传、占比、Peer 数） 显示
lanip 可选 局域网 IP（IPv4），用于 mDNS 修复：把 ICE 候选中的 .local 替换为真实 IP，解决老 WebView 无法解析 mDNS 无
swarmId 可选 固定分组 ID（仅兼容旧用法；互通测试请勿传，默认按流地址分组） 按流地址派生
autoplay 可选 传 0 不自动播放（等用户点播放） 自动播放
muted 可选 传 0 不静音（有声音自动播放可能被浏览器拦截） 静音
controls 可选 传 0 隐藏播放器控制条（纯展示用） 显示

四、iframe 控制 API（父页面调用）

其他网站可通过 postMessage 控制 iframe 内的播放器，播放器也会主动上报状态与 P2P 统计。

父页面 → 播放器（控制命令）

const frame = document.getElementById("player");
frame.contentWindow.postMessage({ type: "p2p:play" }, "*");                                  // 播放
frame.contentWindow.postMessage({ type: "p2p:pause" }, "*");                                 // 暂停
frame.contentWindow.postMessage({ type: "p2p:seek", time: 60 }, "*");                        // 跳转（秒）
frame.contentWindow.postMessage({ type: "p2p:load", url: "https://.../index.m3u8" }, "*"); // 换源
frame.contentWindow.postMessage({ type: "p2p:mute", muted: true }, "*");                    // 静音
frame.contentWindow.postMessage({ type: "p2p:volume", value: 0.8 }, "*");                   // 音量
frame.contentWindow.postMessage({ type: "p2p:getState" }, "*");                             // 请求状态

播放器 → 父页面（状态上报）

window.addEventListener("message", (e) => {
  const d = e.data || {};
  if (d.type === "p2p:ready") console.log("播放器就绪", d);   // 就绪
  if (d.type === "p2p:state") console.log("状态", d);        // playing/currentTime/duration/muted/volume
  if (d.type === "p2p:stats") console.log("P2P", d);         // http/p2p/up/ratio/peers（每秒上报）
  if (d.type === "p2p:error") console.error("错误", d);      // 加载失败等
});

六、P2P 工作方式

  1. 浏览器加载 m3u8 清单 → 通过 WebTorrent Tracker 加入该流的 swarm（对等组）
  2. 同一流地址的观众自动进入同一 swarm，通过 WebRTC 互相连接
  3. 分片同时从 HTTP 源站 和 P2P 邻居 获取，优先 P2P（节省源站带宽）
  4. STUN 打洞 + TURN 中继兜底，穿透公网 NAT（对称 NAT 也能连）

统计悬浮层里的 P2P 占比 反映 P2P 命中率——多人同时观看时占比会显著上升。

七、注意事项

  • ⚠ 单码率流：按流地址分组，不同 m3u8 各自独立 swarm，不互通
  • ⚠ 防盗链流：带 token 且高频刷新的直播流，分片生命周期极短，P2P 命中率会下降
  • ✔ iOS 17.1+：通过 ManagedMediaSource 走 P2P；✖ 老 iOS 自动回退原生 HLS（能播但无 P2P）
  • ✔ 移动端：自动静音播放（iOS 限制）；点击即可开启声音
  • ✔ peerId：网页端以 W-平台 标识（如 W-Win / W-And / W-iOS），便于在 tracker/日志识别设备
